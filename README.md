# Название проекта 

Lore - книжный форум для читателей и авторов 

# Функциональные требования к проекту 

Функционал системы разделен на 4 основных модуля и зависит от ролевой модели пользователя (Администратор, Редактор, Авторизованный читатель, Гость +(Критик)).

# Модуль 1: Аутентификация и управление аккаунтом
Регистрация и Авторизация: Создание учетной записи по Email и паролю, вход в систему с проверкой введенных данных (реализуется на PHP с хешированием паролей).

Управление профилем: Возможность просмотра личных данных читателя и безопасный выход из аккаунта (Logout).

Разграничение прав доступа (Ролевая модель):

Администратор: Полный доступ к панели управления, управление пользователями и глобальными настройками.

Редактор: Доступ к CRUD-операциям (создание, чтение, обновление, удаление) для книг, авторов и жанров, также возможность создания постов, комментариев и ставить отметку нравится.

Читатель: Доступ к чтению, скачиванию, сохранению прогресса и закладкам, также возможность создания постов, комментариев и ставить отметку нравится.

Гость: Только просмотр каталога и карточек книг (без доступа к чтению и скачиванию).

# Модуль 2: Каталог книг (Витрина)
Отображение каталога: Вывод списка добавленных в базу книг в виде адаптивной сетки или списка.

Сортировка: Механизм вывода книг в прямом и обратном алфавитном порядке (А-Я, Я-А).

Система фильтрации и поиска: Возможность для пользователя отсортировать выдачу по следующим критериям (Дата выпуска, автор, жанр).

# Модуль 3: Карточка книги (Детальная страница)
Визуализация и метаданные: Отображение обложки книги, названия, жанра, года выпуска и объема.

Информация об авторе: Вывод имени автора с кликабельной ссылкой для перехода к списку всех его произведений, а также краткая биография/справка.

Аннотация: Текстовое описание и краткое содержание произведения.

Целевые действия: Кнопки «Читать онлайн» и «Скачать» (доступны только для авторизованных пользователей).

# Модуль 4: Книжная лента (Микроблог)
Интерактивная лента коротких публикаций в стиле Threads/X для обсуждения литературы.

Глобальная лента: Вывод постов пользователей в обратном хронологическом порядке с динамической подгрузкой (без перезагрузки страницы).

Создание постов: Публикация коротких заметок (цитаты, мини-рецензии, статусы чтения) с возможностью прикрепить к посту мини-карточку книги из каталога.

Социальное взаимодействие: Система лайков и возможность отвечать на посты.

# Модуль 5: Функционал чтения (Ридер) и взаимодействие
Онлайн-чтение: Встроенный web-ридер для комфортного чтения текста книги прямо в браузере.

Скачивание: Возможность загрузки файла книги (например, в формате PDF). 

Синхронизация прогресса: Автоматическое сохранение текущей позиции чтения (номера страницы) в базу данных. При повторном открытии книги читатель продолжает с того же места.

# Технологический стек 

PHP: Потребуется создать таблицы в БД для posts (посты), comments (ответы), и likes (лайки). В таблице постов нужно предусмотреть поле book_id для связи поста с книгой.

JS: Будет играть ключевую роль для создания ощущения современного приложения. Лайки, разворачивание спойлеров, отправка новых постов и подгрузка старых должны происходить без перезагрузки страницы.

HTML/CSS: Верстка должна быть модульной, чтобы компактная карточка книги (из Модуля 3) легко переиспользовалась внутри блока поста в ленте.

## 1)Author.today

## 1. Технический аудит
Название ресурса: Author.today (ООО "АВТОР ТУДЕЙ")

Адрес в сети: https://author.today

### Архитектура и стек:

Frontend: Vue.js, SPA с элементами SSR для SEO, сборка Webpack.

Backend: .NET / ASP.NET Core.

Взаимодействие: Асинхронные запросы Fetch/XHR (JSON).

Семантика HTML5: Активно используются теги header, main, footer, nav, article(для карточек книг/постов), section (для блоков каталога).

Семантические классы: При верстке div-ами используется БЭМ-подобный нейминг (например: .book-row, .book-card, .book-title, .nav-bar-inner).

Адаптивность: Настроена через CSS media-запросы. Мобильная версия перестраивает сетку в одну колонку, меню сворачивается в "гамбургер", интерфейс ридера скрывает лишние панели управления.

### Анализ Lighthouse:

Условия: Десктоп, Chrome (Инкогнито), Wi-Fi (100 Мбит/с, дом).

Оценки: Performance ~70/100 (снижено из-за тяжелых обложек), Accessibility ~88, Best Practices ~95, SEO ~100.

### Хранилище и Cookies:

LocalStorage/SessionStorage: Хранение настроек ридера (размер шрифта, тема) и предпочтений отображения каталога (плитка/список).

Cookies: Хранение сессий авторизации (.AspNetCore.Session), CSRF-токенов.

Маркетинг и аналитика (Network): Найдены скрипты Яндекс.Метрики (metrika), Google Analytics / Tag Manager (analytics, tagmanager) и пиксель ретаргетинга ВКонтакте (vk.com/rtrg).

## 2) LiveLib.ru

## 1. Технический аудит
Название ресурса: LiveLib.ru

Адрес в сети: https://www.livelib.ru

### Архитектура и стек:

Frontend: React / Next.js, SSR для SEO (признак — мета-тег next-size-adjust, генерируемый модулем оптимизации шрифтов next/font).

Backend: не подтверждено напрямую — требуется ручная проверка через DevTools/заголовки ответа сервера.

Взаимодействие: Асинхронные запросы (обновление ленты, лайков, подгрузка рецензий), предположительно Fetch/XHR (JSON), по аналогии с современными SSR-платформами.

Семантика HTML5: На главной странице прослеживается стандартная структура — шапка с логотипом, основная навигация, подвал с копирайтом и юридическими ссылками; вероятно используются header, main, footer, nav, но без доступа к DevTools точное присутствие article/section для карточек книг и рецензий не подтверждено.

Семантические классы: Точный нейминг классов (БЭМ или иной) не подтверждён — требуется ручная проверка исходного кода через DevTools.

Адаптивность: Настроена через CSS media-запросы (подтверждено мета-тегом viewport). Мобильное/сжатое меню сворачивается в пункт «Еще» (аналог гамбургер-меню). В отличие от Author.today, у LiveLib также есть нативные мобильные приложения (iOS, Android, RuStore), хотя, по отзывам пользователей и ответам разработчиков, их развитие сейчас не приоритетно — основной фокус смещён на веб-версию.

### Анализ Lighthouse:

Условия: Реальный прогон не выполнялся — нет доступа к браузерному окружению для живого Lighthouse-теста. Оценки ниже требуют ручной перепроверки (Десктоп, Chrome Инкогнито, Wi-Fi).

Оценки (ОЦЕНОЧНО, не измерено напрямую): Performance — вероятно ниже, чем у Author.today, из-за большого количества сторонних рекламных/трекинговых скриптов (по данным сторонних профилировщиков технологий — порядка 93 веб-технологий в категориях аналитики, маркетинга и виджетов). Accessibility, Best Practices — не оценивались. SEO — вероятно высокий, метаданные (description, robots: index/follow, verification) настроены системно.

### Хранилище и Cookies:

LocalStorage/SessionStorage: предположительно хранение пользовательских настроек отображения (списком/плиткой, фильтры каталога) — не подтверждено напрямую, требуется проверка через DevTools.

Cookies: сессия авторизации, вероятно CSRF-токен для форм (отзывы, рецензии, комментарии) — не подтверждено напрямую.

Маркетинг и аналитика (Network): Подтверждена интеграция с Яндекс.Вебмастером (мета-тег верификации) и системой мониторинга ошибок Sentry (метатеги sentry-environment, sentry-release, sentry-trace_id на главной странице). По данным сторонних профилировщиков технологий сайт также использует существенно более широкий, чем у Author.today, набор рекламных и аналитических сетей — включая Яндекс.Директ, Google DoubleClick, OpenX, Google AdSense, Amazon Publisher Services.

## 2. Функциональный анализ и приоритеты для проекта "Lore"
На основе конкурента выделены функции для внедрения в MVP "Lore" с распределением приоритетов. В отличие от Author.today (платформа самиздата с читалкой), LiveLib — это социальная сеть вокруг чтения без полнотекстовой читалки, что структурно ближе к формату книжного форума.

### Высокий приоритет (Критично для MVP)
Книжные полки / читательский дневник (Модуль статусов чтения). Отметка книг в статусах «Прочитано / Читаю / Хочу прочитать» без необходимости хранить полный текст книги в системе (по user_id и book_id).

Рецензии и рейтинги (Модуль оценок). Развёрнутый текстовый отзыв + числовая оценка книги с агрегацией в среднюю оценку произведения.

Цитаты как отдельная сущность (Модуль цитат). Пользователи добавляют и лайкают цитаты из книг независимо от рецензий, с привязкой к book_id.

Тематические группы (Модуль форума). Сообщества по жанрам/интересам — прямой аналог структуры книжного форума, ядро продукта для "Lore".

### Средний приоритет
Подборки (Модуль кураторских списков). Пользовательские тематические списки книг — контент для вовлечения и SEO.

Лента активности (Модуль ленты). Агрегированная лента событий по подпискам (рецензии, новые записи на полках, цитаты). Обновление должно происходить асинхронно через JS без перезагрузки страницы.

### Низкий приоритет (Out of Scope / На будущее)
Геймификация. Книжные челленджи, статусы («Эксперт») и книжные игры откладываются до пост-MVP этапов.

Нативные мобильные приложения. Даже у LiveLib это не приоритет разработки последних лет — для MVP Lore достаточно адаптивного веба.

Офлайн-мероприятия и партнёрства с издательствами. Интересно для зрелого сообщества, но не требуется для MVP.
