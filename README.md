# Название проекта 

Lore - книжный форум для читателей и авторов 

# Функциональные требования к проекту 

Функционал системы разделен на 4 основных модуля и зависит от ролевой модели пользователя (Администратор, Редактор, Авторизованный читатель, Гость +(Критик)).

# Модуль 1: Аутентификация и управление аккаунтом
Регистрация и Авторизация: Создание учетной записи по Email и паролю, вход в систему с проверкой введенных данных (реализуется на PHP с хешированием паролей).

Управление профилем: Возможность просмотра личных данных читателя и безопасный выход из аккаунта (Logout).

Разграничение прав доступа (Ролевая модель):

Администратор: Полный доступ к панели управления, управление пользователями и глобальными настройками.

Редактор: Доступ к CRUD-операциям (создание, чтение, обновление, удаление) для книг, авторов и жанров, также возможность создания постов, комментариев и ставить отметку нравится.

Читатель: Доступ к чтению, скачиванию, сохранению прогресса и закладкам, также возможность создания постов, комментариев и ставить отметку нравится.

Гость: Только просмотр каталога и карточек книг (без доступа к чтению и скачиванию).

# Модуль 2: Каталог книг (Витрина)
Отображение каталога: Вывод списка добавленных в базу книг в виде адаптивной сетки или списка.

Сортировка: Механизм вывода книг в прямом и обратном алфавитном порядке (А-Я, Я-А).

Система фильтрации и поиска: Возможность для пользователя отсортировать выдачу по следующим критериям (Дата выпуска, автор, жанр).

# Модуль 3: Карточка книги (Детальная страница)
Визуализация и метаданные: Отображение обложки книги, названия, жанра, года выпуска и объема.

Информация об авторе: Вывод имени автора с кликабельной ссылкой для перехода к списку всех его произведений, а также краткая биография/справка.

Аннотация: Текстовое описание и краткое содержание произведения.

Целевые действия: Кнопки «Читать онлайн» и «Скачать» (доступны только для авторизованных пользователей).

# Модуль 4: Книжная лента (Микроблог)
Интерактивная лента коротких публикаций в стиле Threads/X для обсуждения литературы.

Глобальная лента: Вывод постов пользователей в обратном хронологическом порядке с динамической подгрузкой (без перезагрузки страницы).

Создание постов: Публикация коротких заметок (цитаты, мини-рецензии, статусы чтения) с возможностью прикрепить к посту мини-карточку книги из каталога.

Социальное взаимодействие: Система лайков и возможность отвечать на посты.

# Модуль 5: Функционал чтения (Ридер) и взаимодействие
Онлайн-чтение: Встроенный web-ридер для комфортного чтения текста книги прямо в браузере.

Скачивание: Возможность загрузки файла книги (например, в формате PDF). 

Синхронизация прогресса: Автоматическое сохранение текущей позиции чтения (номера страницы) в базу данных. При повторном открытии книги читатель продолжает с того же места.

# Технологический стек 

PHP: Потребуется создать таблицы в БД для posts (посты), comments (ответы), и likes (лайки). В таблице постов нужно предусмотреть поле book_id для связи поста с книгой.

JS: Будет играть ключевую роль для создания ощущения современного приложения. Лайки, разворачивание спойлеров, отправка новых постов и подгрузка старых должны происходить без перезагрузки страницы.

HTML/CSS: Верстка должна быть модульной, чтобы компактная карточка книги (из Модуля 3) легко переиспользовалась внутри блока поста в ленте.

Frontend: Vue.js, SPA с элементами SSR для SEO, сборка Webpack.

Backend: .NET / ASP.NET Core.

Взаимодействие: Асинхронные запросы Fetch/XHR (JSON).

### Анализ Lighthouse:

Условия: Десктоп, Chrome (Инкогнито), Wi-Fi (100 Мбит/с, дом).

Оценки: Performance ~70/100 (снижено из-за тяжелых обложек), Accessibility ~88, Best Practices ~95, SEO ~100.

### Хранилище и Cookies:

LocalStorage/SessionStorage: Хранение настроек ридера (размер шрифта, тема) и предпочтений отображения каталога (плитка/список).

Cookies: Хранение сессий авторизации (.AspNetCore.Session), CSRF-токенов.

Маркетинг и аналитика (Network): Найдены скрипты Яндекс.Метрики (metrika), Google Analytics / Tag Manager (analytics, tagmanager) и пиксель ретаргетинга ВКонтакте (vk.com/rtrg).

## 2. Функциональный анализ и приоритеты для проекта "Lore"
На основе конкурента выделены функции для внедрения в MVP "Lore" с распределением приоритетов.

Высокий приоритет (Критично для MVP)
Web-ридер с сохранением прогресса (Модуль 5). Встроенная читалка с автоматическим сохранением текущей страницы в БД (по user_id и book_id).

Динамическая фильтрация каталога (Модуль 2). Сортировка и фильтрация (автор, жанр, год) через AJAX/Fetch без перезагрузки страницы. Вывод адаптивной сеткой.

Микроблог / Книжная лента (Модуль 4). Динамическая подгрузка коротких постов через JS. Возможность прикреплять мини-карточку книги к посту (связь через book_id).

Ролевая модель доступа (Модуль 1). Скрытие кнопок «Читать онлайн» и «Скачать» для неавторизованных пользователей (Гостей) на уровне интерфейса и логики PHP.

Средний приоритет
Асинхронные лайки (Модуль 4). Лайки к постам в микроблоге. Обновление счетчика должно происходить мгновенно через JS без обновления страницы.

Система закладок (Модуль 5). Возможность для читателя вручную сохранять закладки на нужных страницах (потребует отдельной таблицы в БД).

Низкий приоритет (Out of Scope / На будущее)
Кастомизация ридера. Выбор темной/светлой темы и шрифтов откладывается; для MVP достаточно чистого базового дизайна.

Сложная защита контента. Продвинутая защита от копирования текста не требуется. Достаточно проверять статус авторизации через PHP перед отдачей PDF-файла для скачивания.
